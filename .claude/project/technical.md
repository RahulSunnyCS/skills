## Architecture

- `bin/claude-pipeline.js` parses `argv`, calls `init`/`sync` from `lib/sync.js`
  with `projectRoot = process.cwd()`.
- `TEMPLATE_DIR = <packageRoot>/template`; `init` copies `agents/`, `commands/`,
  and `pipeline/` wholesale and writes `CLAUDE.md`, then records a version marker.
- Drift model: `.claude/.pipeline-version` stores the SHA-256 of CLAUDE.md at
  sync time. `sync` overwrites agents/commands/pipeline unconditionally but only
  rewrites CLAUDE.md when the template changed, prompting on local edits. Note
  the tradeoff: the version marker's hash only covers CLAUDE.md, so drift in
  `.claude/pipeline/*.md` is still detected by sync's own content comparison,
  but not reflected in the marker hash.
- CLAUDE.md is deliberately thin (~200 lines): identity, the shared-ledger
  contract, a restated set of non-negotiable safety rules, and a pointer index
  into `.claude/pipeline/*.md`. This keeps the bulk of the phase specification
  out of every sub-agent's auto-loaded context — only the orchestrator reads
  `.claude/pipeline/` files, and only the one relevant to the phase it is
  about to run.
- Non-TTY safety: `prompt()` defaults to **NO** when stdin is not a TTY.

## Key Patterns & Conventions

- Zero-dependency, single-purpose modules; no framework, no transpile step.
- `init` is idempotent — refuses if a version marker already exists.
- `.claude/project/` and `.claude/settings.json` are **never touched** by
  init/sync; treat the root `.claude/{agents,commands,pipeline}/` as generated
  — edit `web-dev/template/`, never the dogfooded copies.

## Testing

`web-dev/test/sync.test.js` uses the built-in `node:test` runner (zero new
dependency) and spawns the real CLI (`bin/claude-pipeline.js`) against
throwaway temp directories — it exercises `init`/`sync`/`sync --check`/`setup`
as a user would, not the internals directly. Covers: sha256 marker
correctness, idempotent `init`, `sync --check` drift detection, the local-edit
+ template-changed conflict path, and the non-TTY default-to-NO behaviour of
both `prompt()` and `ask()` (spawned children never get a TTY stdin, so this
also proves those paths never block waiting for input). Run with
`npm run test` from either the repo root or `web-dev/`.

`.github/workflows/ci.yml` runs `npm run lint`, `npm run test`, and
`sync --check` (drift between the root dogfood copy and `web-dev/template/`)
on every push/PR to `main`.

## Gotchas

- npm package root is `web-dev/`, not repo root — `npx github:rahulsunnycs/skills`
  would not resolve the package; the README's `claude-web-dev-skills` name
  assumes a matching repo/path. Flag if distribution behaviour is in scope.
- Dogfooded root copies are generated artifacts; the source of truth for any
  agent/command/pipeline/CLAUDE.md change is `web-dev/template/`. Always run
  `node web-dev/bin/claude-pipeline.js sync` from the repo root after editing
  the template, and commit the regenerated root copy in the same change —
  otherwise `sync --check` in CI fails on drift.

## Pipeline Scope (this repo — scope-down)

This is a ~380-line zero-dep CLI (`bin/` + `lib/sync.js`) plus a template
payload and a small `node:test` suite, **not a web app**. Right-size every
run accordingly:

- **N/A — `e2e-test-writer`**: no UI/HTTP surface, no Playwright. Already
  lane-gated (feature-fast/feature-full only); do not request E2E here.
- **N/A — `pricing-reviewer`**: no billing (see business.md). Never set the
  `pricing` tag.
- **Low value — `performance-reviewer`**: no DB/N+1/scale path. Only engage if
  a change is genuinely perf-relevant (e.g. large-tree copy logic).
- **High value here**: `architecture-reviewer` / `senior-software-engineer`
  (the consolidated Phase 4 reviewer covers this project fine at its current
  size), `security-auditor` (path handling / filesystem writes / prompt
  injection of copied content), `test-writer` (extends `web-dev/test/`),
  `implementor`, `red-team`, `translator`, `docs-writer`.
- **Rare here**: `regression-analyst` and `retrospective-reviewer` — both
  gated to feature-full-and-above or the very-hard/epic split, which this
  project's size and lane mix should reach only occasionally.
- **Lanes**: most work here is `express`, `docs`, or `bugfix-known`; reserve
  `feature-full` for changes to the sync/drift contract or the template
  payload semantics. The Phase-0 lane fail-safe still applies, but no
  `risk_flag` (auth/pii/payment/public-API/admin/upload) is present in this
  codebase, so HIGH-risk escalation should be rare and deliberate.
