```
node web-dev/bin/claude-pipeline.js init           # install pipeline into cwd
node web-dev/bin/claude-pipeline.js sync            # update to latest template
node web-dev/bin/claude-pipeline.js sync --check    # CI drift check (exit!=0 if stale)
node web-dev/bin/claude-pipeline.js --version
```

## Architecture

- `bin/claude-pipeline.js` parses `argv`, calls `init`/`sync` from `lib/sync.js`
  with `projectRoot = process.cwd()`.
- `TEMPLATE_DIR = <packageRoot>/template`; `init` copies `agents/` and
  `commands/` wholesale and writes `CLAUDE.md`, then records a version marker.
- Drift model: `.claude/.pipeline-version` stores the SHA-256 of CLAUDE.md at
  sync time. `sync` overwrites agents/commands unconditionally but only
  rewrites CLAUDE.md when the template changed, prompting on local edits.
- Non-TTY safety: `prompt()` defaults to **NO** when stdin is not a TTY.

## Key Patterns & Conventions

- Zero-dependency, single-purpose modules; no framework, no transpile step.
- `init` is idempotent — refuses if a version marker already exists.
- `.claude/project/` and `.claude/settings.json` are **never touched** by
  init/sync; treat the root `.claude/{agents,commands}/` as generated — edit
  `web-dev/template/`, never the dogfooded copies.

## Testing

**No test framework, no tests, no CI workflow exist today.** This is the
highest-value gap in the repo: `lib/sync.js` has real logic (sha256 hashing,
idempotent init, sync drift + conflict prompts, non-TTY default) and zero
coverage.

## Pipeline Scope (this repo — scope-down)

This is a ~190-line zero-dep CLI plus a template payload, **not a web app**.
Right-size every run accordingly:

- **N/A — `e2e-test-writer`**: no UI/HTTP surface, no Playwright. Already
  lane-gated (feature-fast/feature-full only); do not request E2E here.
- **N/A — `pricing-reviewer`**: no billing (see business.md). Never set the
  `pricing` tag.
- **Low value — `performance-reviewer`**: no DB/N+1/scale path. Only engage if
  a change is genuinely perf-relevant (e.g. large-tree copy logic).
- **High value here**: `architecture-reviewer`, `security-auditor` (path
  handling / filesystem writes / prompt injection of copied content),
  `test-writer` (unit tests for `lib/sync.js`), `implementor`, `red-team`,
  `translator`, `docs-writer`.
- **Lanes**: most work here is `express` or `bugfix-known`; reserve
  `feature-full` for changes to the sync/drift contract or the template
  payload semantics. The Phase-0 lane fail-safe still applies, but no
  `risk_flag` (auth/pii/payment/public-API/admin/upload) is present in this
  codebase, so HIGH-risk escalation should be rare and deliberate.
